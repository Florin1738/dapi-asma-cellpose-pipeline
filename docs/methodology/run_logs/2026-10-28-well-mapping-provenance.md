# Marker-based well provenance

Status: accepted engineering provenance gate; not a new measurement method.

Purpose: prevent acquisition order being mistaken for well or treatment identity.
Inputs: synthetic XY folders with microscope-style markers and optional CSV
plate maps. Private retrospective repairs remain outside this checkout.

Implementation: `src/dapi_norm/well_mapping.py`, integrated into both user-facing
Cellpose runners. Run `python -m pytest tests/test_well_mapping.py` and
`python -m pytest` from the checkout using the project environment.
Outputs: mapped endpoint CSVs and workbook, `final/tables/image_to_well.csv`,
and `final/tables/mapping_validation.json`.

Exact rules: one A-H/01-12 marker per raw TIFF field; unique field IDs;
repeated wells retained separately; supplied treatment maps require exact
assay/well joins and complete metadata. No numerical thresholds or scientific
defaults change. These rules follow input identity semantics, not a biological
assumption; no external scientific sources were needed.

Validation: synthetic tests cover irregular order, repeat wells, missing,
invalid and conflicting markers, incomplete/duplicate treatment maps,
ambiguous assay names, fail-before-model behavior and unmapped export refusal.
Existing scientific tests remain required. Workbook render QA is operational,
not segmentation accuracy validation. Existing visual QC obligations remain;
no new segmentation visuals are generated by a provenance-only repair.

Boundary: absent plate maps permit unlabelled quantification only. A provided
map is checked structurally but cannot establish the actual plate contents.
